# MeshCore ⇄ MAX ⇄ Telegram Bridge

Графическое приложение на **CustomTkinter** для обмена текстовыми сообщениями между каналами MeshCore, чатами MAX и Telegram.

Для каждого канала Mesh задаётся привязка к чату MAX и чату Telegram. Пересылка выполняется только между участниками соответствующей привязки.

## Правила пересылки

| Источник | Получатели | Ограничение текста |
|---|---|---|
| MeshCore | MAX и Telegram | Передаётся весь полученный текст |
| MAX | MeshCore и Telegram | В Mesh — не более 139 символов; в Telegram — полный текст |
| Telegram | MeshCore и MAX | В Mesh — не более 139 символов; в MAX — полный текст |

Ограничение **139 символов применяется только к сообщению, отправляемому в Mesh**. Оно не должно изменять исходный текст, используемый для отправки в MAX и Telegram.

Если при пересылке добавляется имя отправителя или обозначение источника, итоговый текст для Mesh, включая этот префикс, также должен укладываться в 139 символов.

> Полный текст в MAX и Telegram передаётся в пределах ограничений их API. Для сообщений, превышающих допустимый размер одного сообщения, требуется разбиение на части. Наличие такого разбиения необходимо проверить в используемой версии кода.

## Возможности

- Графический интерфейс с настройками подключения.
- Тройные привязки: канал Mesh ↔ чат MAX ↔ чат Telegram.
- Очередь отправки в Mesh.
- Ограничение частоты отправки.
- Контроль доступности радиоустройства.
- Индикаторы подключения и активности.
- Журнал событий.
- Сохранение настроек между запусками.
- Telegram через Telethon и MTProto.
- Опциональное подключение Telegram через MTProxy.
- Отображение телеметрии, доступной в библиотеке и прошивке устройства.

## Требования

- Python **3.10 или новее**.
- Устройство MeshCore с совместимой прошивкой и доступом через последовательный порт.
- Токен бота MAX для работы с MAX.
- Telegram Bot Token, API ID и API Hash для работы с Telegram.
- Доступ к сети для подключения к MAX и Telegram.

Скорость последовательного порта по умолчанию:
```text
115200 бод
```

## Установка

Сохраните полный код приложения в файл:
```text
mesh_max_bridge.py
```

Создайте виртуальное окружение:
```bash
python -m venv .venv
```

Активируйте его.

**Windows, PowerShell:**
```powershell
.\.venv\Scripts\Activate.ps1
```

**Windows, командная строка:**
```bat
.venv\Scripts\activate.bat
```

**Linux / macOS:**
```bash
source .venv/bin/activate
```

Установите основные зависимости:
```bash
python -m pip install --upgrade pip
python -m pip install customtkinter pyserial maxapi meshcore telethon
```

Для использования режима FakeTLS дополнительно установите:
```bash
python -m pip install TelethonFakeTLS
```

Если FakeTLS недоступен, выберите другой поддерживаемый режим MTProxy либо отключите прокси.

> API библиотек `meshcore`, `maxapi` и `telethon` может меняться между версиями. После проверки приложения на вашем оборудовании рекомендуется зафиксировать рабочие версии зависимостей.

На Linux для работы графического интерфейса может понадобиться отдельный пакет Tkinter. Например, в Debian / Ubuntu:
```bash
sudo apt install python3-tk
```

## Запуск

Из каталога приложения выполните:
```bash
python mesh_max_bridge.py
```

Все команды запуска желательно выполнять из одного и того же каталога: конфигурация и сессия Telegram используют относительные пути.

## Настройка MeshCore

Подключите радиоустройство к компьютеру, обновите список портов кнопкой **«⟳»** и выберите нужный порт.

Примеры имён портов:
```text
Windows: COM3
Linux:   /dev/ttyUSB0 или /dev/ttyACM0
macOS:   /dev/cu.usbserial-...
```

Каналы, указанные в привязках, должны быть настроены на самом устройстве MeshCore.

Закройте другие программы, использующие выбранный последовательный порт. Одновременный доступ нескольких приложений может привести к ошибке подключения.

## Настройка MAX

Во вкладке **«Настройки»** укажите токен бота MAX.

Бот должен иметь доступ к чатам из привязок и необходимые разрешения для получения и отправки сообщений.

Пустое поле токена предусмотрено для запуска без MAX.

Пример ID чата:
```text
-12345678912345
```

Замените пример реальным ID своего чата.

## Настройка Telegram

Во вкладке **«Telegram»** укажите:

| Поле | Назначение |
|---|---|
| Bot Token | Токен Telegram-бота, полученный через BotFather |
| API ID | Идентификатор приложения с `my.telegram.org` |
| API Hash | Секрет приложения с `my.telegram.org` |
| Использовать прокси | Включение или отключение MTProxy |
| Сервер | Адрес MTProxy |
| Порт | Порт MTProxy |
| Secret | Секрет MTProxy |
| Тип подключения | Режим соединения с прокси |

**Bot Token и API Hash — разные значения.** Для подключения через Telethon требуются соответствующие учётные данные.

Добавьте Telegram-бота в нужную группу или канал и выдайте необходимые разрешения.

Для получения обычных сообщений группы отключите **Privacy Mode** через BotFather либо назначьте бота администратором. В канале для публикации сообщений боту нужны права администратора с разрешением на отправку.

Используйте точный ID чата. ID супергруппы или канала обычно имеет вид:
```text
-1234567891234
```

### MTProxy

Прокси не обязателен. Если прямое соединение работает, можно отключить его использование.

Для подключения через MTProxy используйте актуальные адрес, порт и секрет своего сервера. Предустановленные значения не гарантируют доступность прокси.

Режим FakeTLS требует совместимой реализации соединения и подходящего секрета.

## Привязки каналов

Во вкладке **«Привязки»** задайте соответствия между каналами Mesh и чатами мессенджеров.

Пример:

| Канал Mesh | Чат MAX | Чат Telegram |
|---|---|---|
| 0 | -12345678912345 | -1234567891234 |
| 1 | -12345678954321 | -1234567895678

Сообщение из канала Mesh `0` направляется в чаты первой строки. Сообщение из одного из этих чатов направляется в Mesh `0` и во второй мессенджер этой же строки.

В конфигурации привязки имеют следующий вид:
```json
{
  "channel_bindings": {
    "0": {
      "max": -12345678912345,
      "tg": -1234567891234
    },
    "1": {
      "max": -12345678954321,
      "tg": -1234567895678
    }
  }
}
```

Это пример структуры привязок, а не полный файл настроек.

Значение `null` обозначает отсутствие привязки к соответствующему мессенджеру.

Для однозначной маршрутизации рекомендуется не привязывать один и тот же чат к нескольким каналам Mesh без проверки поведения вашей версии приложения.

## Очередь и ограничения отправки

Очередь предназначена для регулирования отправки в радиоэфир.

Параметры по умолчанию:

| Параметр | Значение |
|---|---|
| Максимальный размер очереди | 50 сообщений |
| Глобальный интервал rate-limit | 2 секунды |
| Интервал rate-limit для пользователя | 30 секунд |
| Интервал передачи | 1 секунда |
| Интервал проверки радио | 300 секунд |
| Порог последовательных ошибок радио | 3 |

После изменения параметров нажмите **«Применить»**.

Кнопка **«Очистить очередь»** удаляет ожидающие отправки сообщения. Кнопка **«Сброс счётчиков»** сбрасывает статистику.

> Ограничение в 139 символов не равно ограничению в 139 байт. Кириллица и emoji занимают несколько байт в UTF-8. Дополнительные ограничения устройства и прошивки необходимо учитывать отдельно.

## Индикаторы и статистика

Интерфейс отображает состояние Mesh, MAX и Telegram, активность обмена и журнал событий.

Карточки телеметрии могут показывать напряжение батареи, время работы устройства, RSSI, SNR, аппаратную очередь и счётчики пакетов.

Набор доступных значений зависит от версии `meshcore` и прошивки. Если команда или поле отсутствует, соответствующее значение может оставаться пустым.

## Сохранение настроек

Настройки сохраняются в файл:
```text
mesh_max_config.json
```

Сессия Telegram использует имя:
```text
bot_session
```

Telethon обычно создаёт файл:
```text
bot_session.session
```

Не редактируйте конфигурацию одновременно с работающим приложением: сохранение из интерфейса может перезаписать ручные изменения.

### Безопасность

Конфигурация может содержать токены и другие секреты в открытом виде. Файл сессии Telegram также является чувствительным.

Не публикуйте эти файлы, не добавляйте их в репозиторий и ограничьте доступ к каталогу приложения.

Рекомендуемый `.gitignore`:
```gitignore
.venv/
__pycache__/
*.pyc

mesh_max_config.json

bot_session.session
bot_session.session-journal
bot_session.session-wal
bot_session.session-shm
```

При утечке токена отзовите его и создайте новый. При утечке сессии Telegram отзовите соответствующую авторизацию.

## Проверка работы

После настройки нажмите **«Старт»** и проверьте журнал подключения.

1. Отправьте сообщение из Mesh. Оно должно появиться в MAX и Telegram.
2. Отправьте сообщение из MAX. Оно должно появиться в Mesh и Telegram.
3. Отправьте сообщение из Telegram. Оно должно появиться в Mesh и MAX.
4. Отправьте из MAX или Telegram текст длиннее 139 символов. В другом мессенджере должен сохраниться полный текст, а в Mesh — текст не длиннее 139 символов.
5. Убедитесь, что пересланные сообщения не запускают повторную пересылку по кругу.
6. Проверьте, что сообщения из непривязанных чатов не уходят в радиоэфир.

Перед постоянной эксплуатацией протестируйте все направления на своих устройствах и версиях библиотек.

## Устранение неполадок

### Последовательный порт не открывается

Проверьте кабель, драйвер, выбранный порт и отсутствие другой программы, использующей устройство.

На Linux проверьте права доступа к последовательному порту. В зависимости от дистрибутива может потребоваться членство пользователя в группе `dialout` или другой группе доступа к устройствам.

### Telegram не получает сообщения группы

Проверьте ID чата, наличие бота в группе, Privacy Mode и права бота.

Убедитесь, что получены именно сообщения, доступные Telegram-боту: Telegram ограничивает некоторые виды обмена между ботами.

### Telegram не подключается

Проверьте Bot Token, API ID и API Hash.

Если используется прокси, проверьте его доступность, секрет и тип соединения. Для диагностики попробуйте прямое подключение, если оно доступно.

### MAX не получает или не отправляет сообщения

Проверьте токен, ID чата, разрешения бота и сообщения об ошибках в журнале.

### Ошибка об отсутствии метода библиотеки

Сверьте используемый код с API установленной версии `meshcore` или `maxapi`. Такая ошибка может указывать на несовместимость версии зависимости.

### Не отображается телеметрия

Убедитесь, что устройство и библиотека поддерживают соответствующие команды статистики.

### Сообщения пересылаются повторно

Остановите мост и проверьте фильтрацию собственных исходящих сообщений и подавление эха Mesh. Также убедитесь, что не запущен второй экземпляр моста с теми же привязками.

## Ограничения

Мост предназначен прежде всего для текстовых сообщений. Передача вложений, редактирований, удалений и реакций не описана и требует отдельной реализации.

Очередь сообщений находится в памяти процесса. Сохранение конфигурации не означает сохранение ожидающих отправки сообщений после завершения приложения.

При недоступности одного из сервисов доставка не гарантируется без отдельной реализации повторных попыток и постоянного хранилища.

Совместимость с конкретными версиями библиотек, прошивкой и оборудованием необходимо проверить перед эксплуатацией.
